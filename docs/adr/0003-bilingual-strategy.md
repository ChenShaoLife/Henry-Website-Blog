# 全站双语，每篇文章手动写中英两版

最初定的是"博客只中文"，因为手动双语对个人博客来说门槛高、容易半途而废。但用户明确选了手动翻译路线 —— 拒绝了 AI 自动翻译（术语易错）、英文摘要（覆盖率不够）、纯 Chrome 翻译（质量不可控）。承诺：每篇文章在 `src/content/blog/zh/` 和 `src/content/blog/en/` 各写一份，共享 slug，独立 frontmatter。代价：每篇文章实际工作量 1.8-2x，写作节奏会变慢。

为了减轻反向工作流压力，定了**单向孤儿规则**：中文有英文无 = 允许（中文先发，英文后翻）；英文有中文无 = 禁止（不符合"中→英"写作流）。

如果将来发现自己一直在拖英文翻译，导致英文 /blog 长期空白或断更，考虑降级为 ADR-0003 的方案 C（只写英文摘要 summaryEn 字段）。这不是失败，是承认实际写作节奏。

## Considered Options

- **手动翻译**（采用）：质量最高，可持续性赌注最大。
- **AI 自动翻译**（build 时 GPT/DeepL）：零工作量，但技术术语翻译易错，需要校对，反而麻烦。
- **只写英文摘要**：低成本但只服务英文访客的"了解大意"，深入阅读还是中文。
- **靠 Chrome 自动翻译**：零工作量，质量不可控。
